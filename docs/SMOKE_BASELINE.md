# QRRest Smoke Baseline

## Как использовать

Перед крупными изменениями и сразу после них пройдите этот чеклист вручную.  
Цель: быстро подтвердить, что ключевые пользовательские и staff-сценарии не сломаны.

## Smoke-checklist

### Guest QR flow

- [ ] Открыть QR-страницу ресторана (`/qr.php` с валидным контекстом)
- [ ] Убедиться, что меню загружается без ошибок
- [ ] Открыть карточку блюда / модалку (если доступна)

### Cart

- [ ] Добавить несколько блюд в корзину
- [ ] Изменить количество (плюс/минус)
- [ ] Удалить позицию
- [ ] Проверить пересчёт итоговой суммы

### Checkout / order creation

- [ ] Оформить заказ из корзины
- [ ] Убедиться, что заказ успешно создан (без 500/fatal)
- [ ] Открыть экран трекинга созданного заказа

### Staff orders

- [ ] Зайти под staff/waiter в `/staff/orders.php`
- [ ] Проверить, что список заказов загружается
- [ ] Убедиться, что новый заказ виден в списке

### Payment status update

- [ ] Нажать действие обновления оплаты (например, “Отметить оплату”)
- [ ] Проверить успешный ответ без ошибок API
- [ ] Убедиться, что payment status изменился в интерфейсе

### Loyalty search

- [ ] Открыть `/staff/loyalty_scan.php`
- [ ] Найти гостя по телефону (включая форматы `79...`, `+79...`, `89...`)
- [ ] Проверить, что карта/баланс отображаются корректно

### POS open

- [ ] Открыть `/staff/pos.php`
- [ ] Проверить загрузку категорий/блюд
- [ ] Добавить блюдо в корзину POS

### KDS open

- [ ] Открыть `/staff/kitchen.php` или `/staff/kds.php`
- [ ] Убедиться, что экран открывается без Access denied/500
- [ ] Проверить загрузку активных заказов

### Floorplan open

- [ ] Открыть `/staff/floorplan.php`
- [ ] Убедиться, что карта зала открывается
- [ ] Проверить, что связанные API-запросы не падают с 403/500

## Минимальный критерий “готово”

- [ ] Все пункты выше пройдены без критических ошибок
- [ ] Нет новых fatals/500 в логах по ключевым маршрутам
